# 业务模型与边界

到期对象、法律保全令、派生依赖和销毁目标共同决定可销毁性；保全中的子对象会冻结其源对象。

## 实体关系

Batch 关联多个 Subject 与 SourceFile；SourceFile 的原始字节和 SHA-256 不覆盖，RawEvent 引用来源行；RuleVersion 被 Evidence 引用；一次 Run 关联多个 Decision、Evidence、Issue。非法输入留下 Issue，不写出无依据的成功结论。

## 状态和失败

导入与身份校验结束后 Run 进入已校验；有无法判定主体时进入待核，否则已判定。规则版本变化产生新 Run，旧 Decision 保留。源哈希冲突、身份冲突、依赖环、证据缺口和执行失败各有独立错误或问题码。写操作只允许显式沙箱，原始来源保持只读。

## 首版以外的自然扩展

多法域规则冲突、动态视图依赖、软删观察期、介质级擦除证明、外部签名校验、共享对象分摊、撤销请求、证明链复签。以上均未实现。

## 跨失效域副本裁定（replication.py）

存储池携带不可变的失效域与层级；保护契约按对象冻结 guard 选择、裁决 run、源路径与实际文件摘要，guard 不可改写。复制采用预约—落盘—登记两阶段：预约即占用容量（含并发安全的写事务），字节先写临时文件并经独立重读核对、原子改名、最终路径二次核读后才登记台账；损坏文件被隔离，预约拒绝且释放容量。中断可重放，已确认副本与历次核验记录不被覆盖。

裁定不相信任何计数：每次 `adjudge` 逐副本重读文件并哈希，archive_guard 要求一份正确冷副本，availability_guard 要求任一单一失效域退出后仍有正确副本（至少两个不同失效域）。硬阻断给 indeterminate，保护不成立给 at_risk，成立给 protected；只有退役后冷层仍满足保护且存在暖层副本时才允许 retire-warm。暖层退役是存储迁移，不产生 destroy 执行记录，也不能履约删除请求。
